# WLC Blocks — Claude Development Guide

## Project Overview

This project uses Claude agent teams to build WordPress Gutenberg blocks from Figma designs. The output is a WordPress plugin (`wlc-blocks`) containing dynamic blocks built with the Interactivity API, styled with SCSS/BEM, and conforming to WCAG 2.1 AA.

**Target environment**: WordPress 6.5+, PHP 8.1+, WordPress Playground (local dev).

---

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Build | `@wordpress/scripts` (webpack, babel, SCSS) |
| Blocks | Gutenberg block API v3, dynamic (`render.php`) |
| Interactivity | `@wordpress/interactivity` (Interactivity API) |
| CSS | SCSS + BEM methodology |
| PHP | PHP 8.1+, OOP, Composer PSR-4 autoload |
| Dev env | WordPress Playground (`npm start` from project root) |

**Never use**: TypeScript, jQuery, utility CSS classes, direct `wp_enqueue_scripts` for block assets, PHP procedural code (functions instead of classes).

## Plugin Architecture

Plugin slug: `wlc-blocks` | Block namespace: `wlc` (e.g. `wlc/portfolio-card`)

```
plugins/wlc-blocks/
├── wlc-blocks.php          # Bootstrap: autoload + hook registration
├── composer.json           # PSR-4 autoload: "WLC\Blocks\" => "src/"
├── package.json            # @wordpress/scripts
├── src/                    # PHP classes only (PSR-4, OOP)
│   └── Services/
│       ├── BlockRegistrar.php          # Scans build/blocks/ and calls register_block_type()
│       ├── PostTypes/                  # CPT registration classes
│       ├── Taxonomies/                 # Taxonomy registration classes
│       └── Blocks/                     # Block controller classes
│           └── {BlockName}Controller.php
├── resources/              # Frontend source (JS, SCSS, PHP templates)
│   └── blocks/
│       └── {block-name}/
│           ├── block.json
│           ├── index.js        # registerBlockType + edit (imports style.scss)
│           ├── edit.js         # Editor component (live preview + InspectorControls)
│           ├── render.php      # Frontend template — template only, calls controller
│           ├── view.js         # Interactivity API store (viewScriptModule)
│           ├── style.scss      # All BEM styles — frontend source of truth
│           └── editor.scss     # Editor styles — @import './style' + overrides
└── build/                  # Generated by @wordpress/scripts — never edit directly
```

## Design System & CSS Variables

**Always fetch design tokens from Figma via MCP** (`get_variable_defs`, `get_design_context`) before writing any styles. Never hardcode color values, font names, or spacing values in source files.

### Workflow: Figma tokens → theme.json → SCSS → HTML

1. Use Figma MCP to retrieve variable definitions from the design file
2. Map tokens to WordPress `theme.json` presets:
   - Colors → `settings.color.palette`
   - Spacing → `settings.spacing.spacingSizes`
   - Typography → `settings.typography` (fontFamilies, fontSizes)
3. WordPress generates CSS custom properties automatically (`--wp--preset--color--*`, etc.)
4. Reference **only** those variables in SCSS and PHP — never raw hex/px values

### Naming convention

```scss
// Correct — always use WP preset variables
color: var(--wp--preset--color--brand-primary);
padding: var(--wp--preset--spacing--md);
font-family: var(--wp--preset--font-family--primary);

// Wrong — never hardcode (neither raw values nor units directly)
color: #E3002F;
padding: 24px;
padding: 1.5rem;   // still wrong — hardcode, not a variable
```

### Token units: Figma → theme.json conversion

Figma stores all numeric tokens as unitless FLOAT values (e.g. `24`, `48`). Units are assigned when mapping to `theme.json`. Apply the following rules:

| Token type | theme.json unit | Rule |
|---|---|---|
| Spacing (`space/*`) | `rem` | Divide px value by 16 (browser base = 16px). `space/md = 24 → "1.5rem"` |
| Font size (`font-size/*`) | `rem` | Divide px value by 16. `13px → "0.8125rem"`, `17px → "1.0625rem"` |
| Letter spacing (`tracking/*`) | `px` | CSS convention; not a WP spacing preset |

```json
// theme.json — spacing in rem
"spacingSizes": [
  { "slug": "xs", "size": "0.5rem",   "name": "XS" },
  { "slug": "sm", "size": "1rem",     "name": "SM" },
  { "slug": "md", "size": "1.5rem",   "name": "MD" },
  { "slug": "xl", "size": "3rem",     "name": "XL" }
]

// theme.json — font sizes in rem
"fontSizes": [
  { "slug": "tag",  "size": "0.625rem",  "name": "Tag" },
  { "slug": "body", "size": "0.8125rem", "name": "Body" },
  { "slug": "h3",   "size": "1.0625rem", "name": "H3" },
  { "slug": "h2",   "size": "3rem",      "name": "H2" }
]
```

**Never change the root font-size** (`html { font-size: ... }`) — browser default 16px must be preserved for accessibility and rem calculations.

## block.json Standards

Every block must have:

```json
{
  "apiVersion": 3,
  "name": "wlc/block-name",
  "textdomain": "wlc-blocks",
  "editorStyle": "file:./index.css",
  "style": "file:./style-index.css",
  "render": "file:./render.php",
  "viewScriptModule": "file:./view.js"
}
```

- `apiVersion: 3` — always, no exceptions
- `editorStyle` — always `file:./index.css` (webpack output for `editor.scss` via `index.js`)
- `style` — always `file:./style-index.css` (webpack output for `style.scss`)
- `render` — always `file:./render.php` (dynamic blocks)
- `viewScriptModule` — use for Interactivity API (`view.js`); omit if block has no frontend JS
- Attributes: always declare type, default value, and `source`/`selector` where applicable

## SCSS / BEM Rules

- Block root class = BEM block name, prefixed with `wlc-`: `.wlc-{block-name}`
- Elements: `.wlc-{block-name}__{element}`
- Modifiers: `.wlc-{block-name}--{modifier}`
- `style.scss` — all BEM rules for this block (frontend source of truth)
- `editor.scss` — `@import './style'` at the top, then editor-specific overrides/additions
- All values via `var(--wp--preset--...)` directly — no intermediate SCSS variables
- **Zero `border-radius`** — WLC brand rule, applies everywhere without exception
- No utility classes — BEM only
- Mobile-first: base styles for mobile, enhance with `min-width` breakpoints

```scss
// style.scss example
.wlc-portfolio-card {
  color: var(--wp--preset--color--text-main);
  padding: var(--wp--preset--spacing--md);

  &__title {
    font-size: var(--wp--preset--font-size--h3);
  }
  &__image { ... }
  &--featured { ... }
}

// editor.scss example
@import './style';

.wlc-portfolio-card {
  // editor-specific overrides if needed
}
```

## Interactivity API Rules

Use **only** for genuinely interactive elements (filters, toggles, animations triggered by user action).

```js
// view.js
import { store, getContext } from '@wordpress/interactivity';

store('wlc/block-name', {
  actions: {
    toggle() {
      const context = getContext();
      context.isOpen = !context.isOpen;
    },
  },
});
```

```php
// render.php — pass server state
wp_interactivity_state('wlc/block-name', [
  'isOpen' => false,
]);
```

Rules:
- Store namespace = block name (`wlc/block-name`)
- SSR state via `wp_interactivity_state()` in `render.php`
- **Do not use `data-wp-ignore`** — deprecated in WP 6.9
- Every directive requiring an ID must have a unique one (use `wp_unique_id()`)
- Wrap interactive root with `data-wp-interactive="wlc/block-name"`

### Interactivity Router

Use `@wordpress/interactivity-router` when the block needs **client-side navigation without a full page reload** — e.g. paginated lists, taxonomy filters, load-more patterns.

```js
// view.js
import { store, getContext } from '@wordpress/interactivity';
import { navigate } from '@wordpress/interactivity-router';

store('wlc/block-name', {
  actions: {
    async filter() {
      const context = getContext();
      const url = new URL(window.location.href);
      url.searchParams.set('category', context.selectedCategory);
      await navigate(url.href);
    },
  },
});
```

```php
// render.php — mark the region that gets swapped on navigation
<section
  data-wp-interactive="wlc/block-name"
  data-wp-router-region="wlc-block-name"
  <?php echo get_block_wrapper_attributes(['class' => 'wlc-block-name']); ?>
>
  <!-- content refreshed by router -->
</section>
```

When to use the router:
- Filterable grids / portfolio lists with taxonomy switching
- Pagination without page reload
- Any "fetch new server-rendered HTML and swap it in" pattern

When **not** to use the router:
- Simple show/hide toggles — use `data-wp-bind:hidden` / `data-wp-class` instead
- Accordion / modal — pure client state, no server round-trip needed

## Editor Component (edit.js)

`edit.js` must provide a meaningful editor experience — never a static "rendered on the frontend" placeholder.

Required pattern:
1. **Live preview** — use `useEntityRecords` from `@wordpress/core-data` to fetch real content (posts, terms) via REST API and render actual block HTML with BEM classes, so `editor.scss` styles apply correctly
2. **InspectorControls** — expose every configurable block attribute in a sidebar panel using appropriate controls from `@wordpress/components` (`NumberControl`, `SelectControl`, `CheckboxControl`, etc.)
3. **Placeholder fallback** — show `<Placeholder>` with icon and label when no content exists yet

```js
import { useBlockProps, InspectorControls } from '@wordpress/block-editor';
import { PanelBody } from '@wordpress/components';
import { useEntityRecords } from '@wordpress/core-data';

export default function Edit({ attributes, setAttributes }) {
    const blockProps = useBlockProps({ className: 'wlc-my-block' });
    const { records: posts, isResolving } = useEntityRecords('postType', 'my-cpt', { per_page: 3 });

    return (
        <>
            <InspectorControls>
                <PanelBody title="Settings">
                    {/* controls for each attribute */}
                </PanelBody>
            </InspectorControls>
            <section { ...blockProps }>
                {/* render real preview using posts */}
            </section>
        </>
    );
}
```

## PHP Rules

- **OOP only** — classes in `src/Services/`, namespace `WLC\Blocks\`, autoloaded via Composer PSR-4
- Every PHP file starts with `defined('ABSPATH') || exit;`
- **Escape all output**: `esc_html()`, `esc_attr()`, `esc_url()`, `wp_kses_post()`
- **Sanitize all input**: `sanitize_text_field()`, `absint()`, `sanitize_url()`, etc.
- Use `get_block_wrapper_attributes()` in `render.php` to merge editor-set classes/styles
- **Doc comments** — every PHP file, class, and method must have a docblock:

```php
/**
 * Handles data preparation for the Portfolio Grid block.
 *
 * @package WLC\Blocks
 */
class PortfolioGridController {
    /**
     * Returns all data needed to render the block.
     *
     * @param array $attributes Block attributes from the editor.
     * @return array{posts: array, filters: array}
     */
    public function getData(array $attributes): array { ... }
}
```

### Block Controller pattern

Every block with non-trivial logic must have a controller class in `src/Services/Blocks/{BlockName}Controller.php`. The controller handles data fetching and processing; `render.php` is a template only.

```php
// src/Services/Blocks/PortfolioGridController.php
class PortfolioGridController {
    public function getData(array $attributes): array {
        // WP_Query, taxonomy queries, data mapping — all logic here
    }
}

// resources/blocks/portfolio-grid/render.php — template only
<?php
defined('ABSPATH') || exit;
$data = (new \WLC\Blocks\Services\Blocks\PortfolioGridController())->getData($attributes);
?>
<section <?php echo get_block_wrapper_attributes(['class' => 'wlc-portfolio-grid']); ?>>
    <?php foreach ($data['posts'] as $post) : ?>
        <article class="wlc-portfolio-card">
            <h2 class="wlc-portfolio-card__title"><?php echo esc_html($post['title']); ?></h2>
        </article>
    <?php endforeach; ?>
</section>
```

## HTML / Accessibility (WCAG 2.1 AA)

- **Semantic HTML5**: use `<article>`, `<section>`, `<nav>`, `<main>`, `<header>`, `<footer>` appropriately
- **Contrast**: minimum 4.5:1 for body text, 3:1 for large text and UI components
- **Images**: every `<img>` must have `alt`; decorative images use `alt=""` + `aria-hidden="true"`
- **Focus**: all interactive elements must have a visible focus indicator (do not use `outline: none` without replacement)
- **Labels**: every interactive element without visible text needs `aria-label` or `aria-labelledby`
- **Card pattern**: link wraps the title; image has `aria-hidden="true"` to avoid duplicate announcements

```php
// Card link accessibility pattern
<article class="wlc-portfolio-card">
    <a href="<?php echo esc_url($url); ?>" class="wlc-portfolio-card__link">
        <img src="..." alt="" aria-hidden="true" class="wlc-portfolio-card__image">
        <h2 class="wlc-portfolio-card__title"><?php echo esc_html($title); ?></h2>
    </a>
</article>
```

## Build & Dev Workflow

```bash
# Start WordPress Playground (from project root)
npm start

# Inside the plugin directory (plugins/wlc-blocks/)
npm install
composer install
npm run start    # watch mode — requires --experimental-modules flag
npm run build    # production build — requires --experimental-modules flag
```

Both `start` and `build` scripts in `package.json` **must** include `--experimental-modules` for `viewScriptModule` (`view.js`) to compile correctly as an ES module.

WordPress Playground mounts `./plugins/` to `/wordpress/wp-content/plugins`. Any plugin folder created there is immediately available in WP Admin. Activate the plugin manually after first build.

## Safety Rules

- Never edit files inside `build/` — they are generated
- Never commit `node_modules/` or `vendor/`
- Never use `wp_enqueue_scripts` / `wp_enqueue_style` for block assets — registration is handled via `block.json`
- Never add global styles in plugin PHP — use `theme.json` or block-scoped stylesheets
- Never hardcode design token values (colors, spacing, font names) — always via `var(--wp--preset--...)`
